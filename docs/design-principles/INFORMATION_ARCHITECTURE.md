# Suchenl 全站信息架构设计原则

> 本文件是个人主页的长期信息架构契约，中文维护。它定义栏目职责、导航与内容归属，不是临时待办。原则生效不代表所有前端功能已经完成；实现与验收记录请见 `docs/RESEARCH_ARCHITECTURE.md`。

## 一、网站定位与设计目标

个人主页同时服务三种任务，但不混成一个通用文章列表：

1. **身份与成果**：让学术同行、合作者迅速确认研究方向、公开论文、项目、作者身份及联系方式。
2. **公开研究知识库**：通过领域、技术专题、论文解读、技术问答及研究探索建立可持续积累的知识体系。
3. **独立表达**：通过博客陈述个人观点、研究实践和公开思考，不把事实汇总强行包装成观点。

优先满足三种路径：首次访问的研究同行能迅速了解代表性成果；带着技术问题来的读者能从专题找到解释和证据；通过论文链接来的读者能回到研究脉络。

基本原则：**以研究问题和知识关联组织阅读，以单一事实源维护内容，以公开、可核验信息呈现成果。**

## 二、全站一级导航

一级导航稳定收敛为五项：

| 一级栏目 | 页面 | 唯一主要职责 |
| --- | --- | --- |
| 首页 / Home | `/` | 身份、研究定位、代表性论文、少量精选探索、可用入口 |
| 研究 / Research | `/research/` | 研究领域与专题、论文解读、问题与探索、术语和全部知识检索 |
| 产出 / Outputs | `/outputs/` | 论文、公开研究实现与开源项目的统一入口 |
| 博客 / Blog | `/blog/` | 独立技术文章、观点、随笔 |
| 经历 / Experience | `/work/` | 教育、科研与实习经历 |

- “论文解读” `/paper-notes/`、“问题与探索” `/questions/` 是 **研究** 的二级浏览入口；原 URL 和正文保留。
- “论文” `/publications/`、“项目” `/projects/` 是 **产出** 的二级浏览入口；原 URL 和公开数据保留。
- 一级导航的激活状态必须覆盖其二级页面；二级页面需提供可以返回领域/上级的可见链接。
- 科研资产库 `https://openresearchassets.github.io/` 是独立公开产品，首页与相关位置提供清晰的外链，不在主页复制其资产目录。
- 目录层级不能仅依赖下拉悬浮菜单；键盘、触控和移动端必须可访问。
- 未有真实内容的栏目不创建空页面、虚假计数或“即将上线”入口。

## 三、Research 的两条组织维度

**领域（domain）说明知识属于哪个研究方向；内容类型（contentType）说明这是怎样的知识对象。** 两个维度独立，不能用文件夹或“博客/论文”概念替代领域。

领域的唯一数据源为 `knowledge/taxonomy.json`，现有四大领域保留：大模型与强化学习、多模态学习与生成、机器人与具身智能、世界模型与环境交互。下级领域只有确有收录需求才增加。

当前内容类型由 taxonomy 统一给出：paper（论文解读）、review（技术综述/专题入口）、qa（技术问答）、exploration（研究探索）、plan（研究计划）、glossary（术语解释）、path（学习路线）。对外展示时应区别 **技术专题**（导航型知识单元）与 **专题综述**（解释型文章），但不必为专题强行增加一份新的正文类别。

**推荐知识路径：领域 → 技术专题 → 概念/论文/综述/研究问题。** 用户也可从论文解读、探索列表、全文搜索进入同一正文。专题不是单一数据库表，而是该领域内的知识导航单元。相关关系必须有明确机制或内容证据，不能仅靠关键字相似。

## 四、内容边界与唯一数据源

| 对象 | 正文的事实源 | 展示规则 |
| --- | --- | --- |
| 公开学术论文、公开项目 | 既有论文和项目数据源 | 首页/产出聚合引用同一份数据，不复制成果描述 |
| 研究知识内容 | `knowledge/` 下的唯一 Markdown | 论文、技术问答、探索、专题从不同入口引用，不产生平行副本 |
| 内容所属领域与类型 | Markdown frontmatter + `knowledge/taxonomy.json` | 一个条目可归属多个领域，类型只能准确描述其认知任务 |
| 研究关联 | 已核验的 Markdown 链接、人工 `related` 与学习路径 | 反向链接不是学术引用次数；未证实的继承和因果关系不得自动生成 |
| 设计原则 | `docs/design-principles/` | 正式原则唯一、中文为主，不增加含义冲突的补丁文件 |

**公开边界是硬约束**：私人仓库、内部合作信息、未公开实验、未公开论文和未经授权的资产，不因知识整理或自动生成而进入公开个人主页。

## 五、全站信息密度与阅读顺序

- 首页展示“身份与研究兴趣 → 代表性公开成果 → 少量研究探索 → 导航入口”，而不是全文摘要、完整实验表格或外部资产复制列表。
- 研究首页首先展示四大研究领域和真实存在的专题入口，然后提供论文解读、问题与探索、全文搜索及高级筛选。
- 领域页展示领域说明、实际专题、精选论文/研究问题及进入全部条目的链接，不为凑数量虚构内容。
- 专题页提供：一句话定位、知识地图、按问题组织的阅读顺序、关键概念/论文/研究问题、证据和更新边界。没有内容的板块不显示。
- 文章阅读页要持续回答“我在哪里 → 这篇讲什么 → 属于哪条研究线 → 还有什么相关内容”，并保留原始来源。
- 搜索、领域筛选与 URL 状态可共存；导航层级的调整不能删除已有高级检索能力。

## 六、链接、国际化与可访问性

- 旧的 `/paper-notes/`、`/questions/`、`/publications/`、`/projects/`、`/research/...` 长链接必须继续可访问；必要迁移需提供重定向，不允许靠删除旧路由制造 404。
- 新导航与入口支持简体中文和英文标签；中文为主，英文为辅。中文页面不得残留大段未解释英文营销文案，英文浏览状态不能出现中文导航标签。
- 研究文章正文可按现有审查状态逐步双语化，不用未经核验的机器译文冒充完整英文正文。
- 目录、面包屑和相关卡片应有准确的链接目标；新动态页面需有标题和描述元信息。
- 响应式优先保证 320/390px 手机、宽屏、键盘焦点、ARIA、长公式与 SVG 可读性。仅 `npm run build` 成功不代表视觉和交互已通过。

## 七、实施与验收边界

依次实施：P0 设计原则与导航 → P1 研究领域/专题入口 → P2 文章阅读关联和目录 → P3 首页/产出聚合与内容密度 → 构建、链接、移动端及语言状态回归。禁止为了一次改版重写原有文章正文、改变读者研究判断或引入无必要的数据库服务。

核心验收：
- 五个一级导航可用且子页面高亮正确；
- 四个领域均可进入有效页面，展示真实已有内容；
- 研究专题有领域返回路径、文章关联与原始来源；
- 论文、问答和探索仍使用原 Markdown；
- Research 的全文检索、筛选、目录和回跳状态无回归；
- 旧页面 URL 和重要外部链接可访问，页面不出现私人研究内容；
- Astro 构建、知识校验、视觉和移动端测试分别报告真实状态。

## 八、与其他原则的关系

- 论文怎么讲透：`PAPER_NOTES.md`。
- 专题与阅读器如何呈现：`RESEARCH_TOPICS_AND_READING.md`。
- 本文件只统领信息架构和栏目边界，避免重复定义论文细节。
