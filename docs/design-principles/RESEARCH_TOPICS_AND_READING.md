# 研究专题与长文阅读设计原则

> 本原则管辖公开 Research 的领域页、技术专题页、专题关联、长文阅读器及二级浏览入口；以中文维护。与论文内容模板并行，不能替代 `PAPER_NOTES.md`。

## 一、以技术专题而不是页面类型组织知识

每个专题必须明确核心技术问题、所属研究领域、知识范围与边界。一篇论文可以属于多个专题；专题不复制论文解读、技术问答或探索正文。各专题导航依据真实的 `knowledge/topics/<topic>/README.md` 和 frontmatter/链接组织。

专题最少要有：问题导向的一句话简介、研究范围、推荐阅读顺序、相邻概念或专题；可以在内容实际存在时展示知识地图、方法比较、代表性论文、研究问题及最后核验日期。**不存在的数据不需要创建占位模块。**

例如“深度感知与几何估计”串联：深度获取 → 立体视觉 → ToF/结构光 → 单目/多视角估计 → RGB-D 融合 → 可信度 → 标定与任务评估。不要误将“有深度数值”当作“有可信三维证据”。

## 二、领域页和专题页的分工

**领域页**解决“这条大研究线包括哪些知识、从哪里进入”；必须用统一分类源生成，显示真实专题与内容条目。

**专题页**解决“为了理解这个具体问题，应按什么路径阅读”；维护经过人工确认的章节顺序，连向已有知识正文、论文和开放研究问题。专题页本身可以是结构良好的 Markdown 文章，而不需要独立 CMS。

**论文解读列表**解决“找一篇论文”；**问题与探索**解决“看正在追问的问题”；**全文知识列表**解决“跨领域搜索/过滤”。这些是同一个知识库的不同视图，不得维护平行 Markdown。

## 三、长文阅读器的共同框架

全部 Research 正文使用一致的层级：研究首页 → 所属领域 → （有明确所属关系才出现）技术专题 → 当前文章。论文解读另有论文列表的返回入口。

阅读器必须提供：
1. 可展开/收起的左侧章节目录，桌面端在阅读时保持可用；移动端改为可展开面板，而非占据正文宽度。
2. 清晰的面包屑、文章标题/概述、准确内容类型、可核验的原文与 Markdown 入口。
3. 长公式、SVG、大表格不应导致全站水平溢出；文字、箭头和标签需可读。
4. 关联内容分开表达：显式机制关联、正文引用、被谁链接、学习路径前后步骤、同领域论文或专题。不能把弱相关排成强因果关系。
5. 搜索/筛选来源与阅读进度恢复时，不能破坏旧浏览现场；用户主动阅读状态与本地临时进度明确区分。
6. 目录、按钮和链接在键盘与手机端有足够触控范围与清晰焦点。

## 四、内容质量与阅读路径

单篇解读遵守“先懂概念与机制，再看实验和证据，最后形成研究判断”。专题总览则应优先展示概念之间的结构，避免正文开头塞入长篇论文摘要。

- 概念定义和论文具体作用分清，复用统一术语页；
- 重要技术图用可编辑 SVG 和明确的标题/来源，图为理解服务；
- 每篇深度解读连接到原论文或一手资料，标注推论、适用边界与尚待核验；
- 文章底部给出返回所属领域、相关专题和下一步阅读的路径；
- 未有直接证据的相关关系要标明“同领域延伸阅读”，不要写成“验证了”“继承了”。

## 五、实现与治理

优先复用 Astro 既有 `getCollection('knowledge')`、`knowledge/taxonomy.json`、图谱以及阅读器脚本。新专题页无需二次存储，也不应因前端聚合而改变任何已确认的研究判断。非公开项目、未发表实验及私人研究方向不可根据链接猜测后生成公众页面。

新增专题、调整分类、迁移页面前先检查现有路由、脚本和回归约束。至少验证 Astro 构建、研究内容校验、旧深链、手机目录以及桌面 TOC，无法验证的浏览器/交互测试需明确标记“未验证”。
