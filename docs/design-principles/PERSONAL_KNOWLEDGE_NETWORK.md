# 个人知识体系与可点亮知识网络：设计原则

> 本文件定义 Knowledge（/knowledge/）的长期语义和验收要求。中文优先，英文界面必须有相应的基本操作标签。继续遵守 INFORMATION_ARCHITECTURE.md 的公开边界、唯一正文和旧 URL 兼容原则。

## 一、定位

Knowledge 是个人长期知识体系的公开阅读面：研究、数学、工程、设计与思考方法可共存，研究并不代表全部知识。首页上方应先呈现「知识网络」和可达入口，下面才是列表、按类型阅读与研究入口。不得把网站变成只有统计数字的仪表盘。

## 二、真实知识网络与节点状态

- **领域**：广义知识领域，既有研究领域直接读取 knowledge/taxonomy.json；未建设的非研究领域暂由 graph-roadmap.json 显式列为规划节点，不在没有正文时生成伪文章。
- **专题节点**：使用稳定 ID，挂载到领域，允许真实 Markdown 属于多个专题。图上关系分为 `belongs_to`（分类层级）和人工有依据的 `related_to`（跨专题关联）；不允许 AI 根据词语相似随意断定前置依赖、因果或证明。
- **内容覆盖状态**：有至少一条已公开且带匹配 domains 元数据的正文，表示「已有资料」，不是「学懂」或「完整掌握」；无匹配正文表示「待建设」；某领域子专题尚未覆盖齐全表示「建设中」。
- **学习状态**：与覆盖状态完全独立，只有读者主动确认「已学习」才能标记。浏览器本机的自愿标记必须注明不同设备不自动同步，也不表示本站作者的学习记录。
- 统计范围与规则必须可读；新文章通过构建自动更新图，不要复制 Markdown 正文到图谱数据。

## 三、图谱交互

- 图放在 /knowledge/ 首屏；可选节点、搜索、按有无内容筛选、通过可访问链接阅读真实正文。必须能用键盘完成基本操作，移动端可以改用清晰列表与横向滚动画布，不能把信息仅藏于视觉图形。
- 图谱的节点说明包含状态、已有条目数量、与可阅读资料链接；没有资料时提供「向 AI 提出补全任务」的可复制提示词，而非假装调用模型或自动创建公开文章。
- AI 辅助的流程是「明确专题 → 查重与来源核验 → 生成草稿 → 作者审查并授权公开 → 发布到唯一正文 → 图谱自动亮起 → 人类再学习」。AI 写出草稿不代表内容已验证，更不代表本人已掌握。
- **不披露隐私**：不把私人仓库、内部文档、个人学习历史、未发表研究自动同步或暗示到公开页面。不得提供未经授权的一键发布。
- 连接关系中的待验证假设应明确提示，不混入正式知识边。

## 四、内容模型与扩展

延续现有 `knowledge/` 的唯一 Markdown 正文；研究元数据沿用现有 taxonomy 和 frontmatter。将来新增真正的非研究公开文章时，先扩展通用的领域/专题注册与统一 schema，内容再进入 `knowledge/` 的新合法类型，而非把非研究硬塞进 `research/`。

规划节点不是知识的完成声明，随实际内容和使用反馈逐步新增、删改；不要为了做满图谱而大批创建空内容页。

## 五、验收

- 图谱首屏可见，能找到真实深度感知、机器人控制、已有研究专题与明确未建设节点；
- 所有点亮统计来自真实带分类的公开 Markdown，新增/删除正文后自动变化；
- 点击已有节点至少能打开相关的唯一知识正文；空节点能生成可审核的 AI 补全任务；
- 能区分内容覆盖/个人学习，且本机学习标记由用户明确操作；
- 移动端、键盘、语言切换、图谱退化为可读列表、旧 /research/ 链接以及生产构建应验收；
- 未覆盖的后续项目（跨设备学习同步、后台 AI 自动生产、全文跨学科分类迁移）在状态记录明确列为未实现。
