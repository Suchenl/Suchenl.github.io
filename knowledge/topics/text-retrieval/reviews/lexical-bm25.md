# TF-IDF 与 BM25：关键词检索为什么需要排名

## 一句话总结

**BM25 是一种词法相关性排序函数：它奖励文档匹配查询中的有区分度的词，同时限制重复堆词的收益，并考虑文档长短。它不会神奇地理解词汇不同的同义表达。**

## 1. 从 Boolean Retrieval 走到 Ranked Retrieval

假设 Query 为“visual servoing robot”。

布尔查询可以找出同时出现这些词的文档，却不能回答哪篇更加相关。Ranked Retrieval 的目标是在候选中分配一个相关性分数，返回 Top-K。

这里首先出现三个概念：

- **TF (Term Frequency)**：查询词在当前文档出现多少次。
- **DF (Document Frequency)**：语料库里有多少篇文档包含这个词。
- **IDF (Inverse Document Frequency)**：包含该词的文档越少，它通常越能区分文档。

例如“the”在几乎每篇英文论文都出现，通常不足以区分相关文档；而“visual servoing”相关的技术词可能更有辨识度。

## 2. TF-IDF 是什么？

一种典型的 TF-IDF 权重写法为：

$$
w(t,d)=\mathrm{tf}(t,d)\,\log\frac{N}{\mathrm{df}(t)}
$$

其中 N 是文档数，df(t) 为包含词 t 的文档数。实际系统可能采用平滑、对数 TF、向量长度归一化和其他变体。

TF-IDF 的直觉是：**某词在这篇文档中出现得多，而在其他文档里相对少，说明它有更强的局部代表性。**

但线性的 TF 项可能让重复堆叠关键词过度加分；文档长度也会影响词频。

## 3. Okapi BM25 的公式

一种常见的 BM25 形式是：

$$
\operatorname{BM25}(q,d)=
\sum_{t\in q}
\log\!\left(1+\frac{N-\mathrm{df}(t)+0.5}{\mathrm{df}(t)+0.5}\right)
\frac{\mathrm{tf}(t,d)(k_1+1)}
{\mathrm{tf}(t,d)+k_1\left(1-b+b\frac{|d|}{\mathrm{avgdl}}\right)}
$$

解释为三部分：

1. **IDF**：稀有词的权重通常更高。
2. **TF 饱和**：词出现 1→2 次通常比 50→51 次带来的额外收益大；k1 决定饱和速度。
3. **长度归一化**：文档很长，词出现次数多不一定值得同等程度加分；b 控制长度修正。

常见演示参数为 k1≈1.2、b≈0.75，但不是普适最优值。b=0 相当于关闭这一长度修正，b=1 时按长度比例完全启用这一部分修正。

### 一个便于理解的数值直觉

同一个查询词在长度相近的文档中：

| 匹配次数 | 词法评分的变化趋势 |
| --- | --- |
| 0 | 该词贡献为 0 |
| 1 | 获得初始贡献 |
| 2 | 继续加分，但边际收益缩小 |
| 20 | 仍可能增加，但已接近饱和 |

这张表解释趋势，不代表一组固定 BM25 分数；实际结果取决于 N、df、长度及参数。

## 4. BM25 与 grep 的区别进一步明确

- grep -F 搜索固定字面串，通常返回**匹配行及其位置**。
- grep -E 搜索正则模式，关注**模式是否出现**。
- BM25 对经过分词和索引的查询词集合评分，关注**相对相关性排序**。
- BM25 可以与倒排索引组合，使用 Posting List 快速筛出候选并算分。

它们不是“从低级工具升级为高级工具”的单向替代关系：找精确 API 名称时，grep 或精确字段查询常常更可靠。

## 5. 中文检索为什么更依赖 Analyzer？

中文文本没有天然的空格分词边界。Query“机器人视觉伺服”可能被切成“机器人 / 视觉 / 伺服”，也可能采用字符 n-gram 或其他粒度。

这意味着即使使用相同 BM25 公式，**分词器、大小写、同义词规则、停用词与字段配置**都可能显著影响结果。

英文论文里的“IBVS”和“image-based visual servoing”若未使用缩写扩展或同义词表，基本 BM25 不会自动识别它们的关系。

## 6. BM25、BM25F、短语匹配有何区别？

| 方法 | 特点 |
| --- | --- |
| BM25 | 以词项统计和长度修正进行词法排序 |
| BM25F | 将标题、摘要、正文等多个字段的匹配信息纳入统一的字段加权框架 |
| 短语/邻近查询 | 依赖词位置，限制相邻次序或距离 |
| 字段过滤 | 限制年份、作者、文档类型等结构化条件 |

这些机制可以组合，不必强迫一个 BM25 分数承担所有工作。

## 7. 何时选 BM25？

特别值得优先考虑的场景：作者名、论文标题、库名、函数名、错误码、专业术语、法律条款编号、版本号。常与 Dense Retrieval 互补。

不建议把 BM25 命中分数解释成“文档正确的概率”，也不能只凭它证明检索到的段落支持最终答案。

## 思考检验

- 为什么某个关键词在 10 篇文章中出现，比在 90% 的文章中出现通常更有判别性？
- 在 BM25 公式中，为什么 tf=100 不会简单得到 tf=1 的 100 倍贡献？
- 只要换成 BM25，就一定能搜索到同义词表达吗？为什么？
