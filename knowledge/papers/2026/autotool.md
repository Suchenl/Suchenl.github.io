# AutoTool: Dynamic Tool Selection and Integration for Agentic Reasoning

- **中文主题**：动态工具选择：先稳住推理轨迹，再训练工具排序与泛化
- **作者**：Jiaru Zou、Ling Yang、Yunzhe Qi 等
- **首次公开 / 发表时间**：2026-07
- **发表状态**：ICML 2026 正式论文
- **原始来源**：[论文或官方页面](https://proceedings.mlr.press/v306/zou26p.html)
- **标签**：动态工具库 / SFT / RL / 排序 / Agent
- **原文核验**：2026-10-19；核验范围：原文/官方摘要（方法及实验中的进一步细节需查原论文表格）

## 研究问题
很多 Agent 训练假定固定工具集合，然而实际部署可能不断新增 API，模型需要理解工具描述并动态选择，不能只记工具名称。

## 方法
第一阶段使用 SFT 加 RL 稳定多步推理轨迹，使模型形成合理的“分析—工具调用—结果利用”行为；第二阶段使用带 KL 正则的 Plackett–Luce 排序训练工具选择一致性。论文构建约 20 万条包含明确工具选择理由的数据，覆盖 1,000 多工具、100 多任务。

## 论文实验
在 Qwen3-8B、Qwen2.5-VL-7B 上，作者报告十个基准的平均收益：数学/科学 6.4%、搜索问答 4.5%、代码生成 7.7%、多模态理解 6.9%（均为其具体对照设置）；强调新工具泛化。需要核对各领域指标与数据泄漏控制再做横向比较。

## 局限
研究依赖额外的大规模工具选择解释数据；这正是 ORA 当前有疑问的环节。工具被正确排序不代表机器人可以安全、有效执行。动态工具目录能力与任务完成能力必须分开报告。

## ORA 启发
不应把几十个工具一次性塞给模型再期待 RL 随机探索；先评估“工具检索候选 + 最终工具选择”与固定少量原生工具基线。后续若开放大量工具，更适合研究按需发现和可验证工具排序。
