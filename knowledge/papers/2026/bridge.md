# Beyond Two-Stage Training: Cooperative SFT and RL for LLM Reasoning

- **中文主题**：BRIDGE：让 SFT 学会只在有利于奖励优化时监督 RL
- **作者**：Liang Chen、Xueting Han、Li Shen、Jing Bai、Kam-Fai Wong
- **首次公开 / 发表时间**：2026-07
- **发表状态**：ICML 2026 正式论文
- **原始来源**：[论文或官方页面](https://proceedings.mlr.press/v306/chen26an.html)
- **标签**：联合梯度 / 元学习 / 协同训练 / LoRA
- **原文核验**：2026-10-19；核验范围：原文/官方摘要（方法及实验中的进一步细节需查原论文表格）

## 一句话结论
不是所有正确的 SFT 更新都能提高 RL 的最终奖励；BRIDGE 研究的是**选择性地传递 SFT 梯度**，让两类目标共同改善回报，而非直接把两个 Loss 加权求和。

## 1. 为什么加权和不够？
设监督梯度为 `g_SFT`，强化梯度为 `g_RL`。如果点积为负，说明在当前参数附近二者倾向不同：一次 SFT 更新可能拉低 RL 正在优化的策略回报。固定权重 `α g_SFT + β g_RL` 并不会自动解决这种冲突。

## 2. 方法流程
论文提出一个双层优化（meta-training）机制：在每个元训练阶段，先进行结合 SFT/RL 信息的基模型参数更新；随后更新一个轻量 LoRA 组件，利用“联合训练相对纯 RL 的奖励增益”（cooperative gain）来学习应当如何协调两个目标。读者应将它理解为**SFT 梯度有条件帮助 RL**，而不是把 LoRA 当作另一个独立最终模型。

## 3. 论文报告
在五个数学推理基准上，该方法较所比较的两阶段、朴素混训等方案平均绝对提升**超过 3 个百分点**；作者还报告对逻辑推理和 OOD 代码/科学任务的适用性。应检查论文表格中的模型规模、基线及元优化附加开销，不能将结果解释为 Agent 闭环成功率的提升。

## 4. 批判性分析
协同增益依赖可靠、及时的 RL Reward。如果奖励只反映“像不像示范轨迹”，元优化可能会选择更利于模仿的监督，而不是更利于真实物理任务的监督。需要考虑更复杂的训练/验证双重开销，尤其是大模型工具 Rollout 的 stale policy 问题。

## 5. 迁移启发
ORA 如果未来用同一步 SFT+RL 梯度更新，应先测量 `cos(g_SFT,g_RL)`、两种 Loss 的尺度和任务回报；仅在证明梯度冲突实际严重时，引入 BRIDGE 类元优化。
