# 研究提议：SFT Loss 不变，让 RLVR 从真实机器人演示中学习可变动作进度

> **状态**：研究假设 / 待实验；不是已完成实现或已验证的方法。**首次记录：2026-10-19**。  
> 背景阅读：[SFT × RL 主题综述](../topics/llm-agent-training/reviews/sft-rl-co-training.md) · [DTWIL](../papers/2025/dtwil.md) · [术语](../glossary/agent-training.md)。

## 0. 核心观点

**保留现有的自回归 SFT Cross-Entropy 与因果 Attention Mask，不在 SFT 中为每条动作强行构造可微几何损失。**

对 RLVR，模型自己生成 `robot_act` 工具调用及参数，从原始成功演示计算一个**轨迹相容性/安全幅度/进度的标量奖励**，通过 Policy Gradient/GRPO 对本次输出的 token 更新策略。

它允许动作幅度与示范 next chunk 不完全一致，只要该动作能在已知的几何意义下对齐到一个**局部、顺序合法、执行约束内的未来轨迹段**。这个主张相当于“离线演示约束的策略优化”，而不是传统的逐时刻 BC。

### 为什么不改 SFT Loss？

模型输出的是离散语言 token（结构化 JSON 工具调用）。如果直接把 JSON 解析出的离散数值拿去计算几何 Soft-DTW，并不能自动穿过 token Sampling 恢复成普通连续 Loss 的反向传播。新增连续动作 Head、修改 packing/mask/训练序列都可能增大工程风险。保留已有 SFT 路径可以避免这个无关复杂度。

**需要纠正一个细节**：连续几何 Loss 并非天然要求修改 Transformer 的 causal attention mask；更准确的困难是如何让生成的结构化数值动作对参数保持可微、如何选择监督目标并保证训练与工具执行契约一致。

## 1. 样本和训练过程（第一版无仿真）

有一条成功演示 `D={o_t,T_t,g_t,a_t}`；`o_t` 是已录制图像与实测状态，`T_t∈SE(3)` 是 TCP 位姿，`g_t` 是夹爪/接触阶段。

- 提供一个历史时刻 `t` 的**当前可见**观测及用户任务，模型生成一个 `robot_act`（含平移、旋转、抓手）。
- 解析工具命令，并用已知的机器人坐标系/当前 FK 计算**预测的目标 TCP 位姿** `T_hat`。不能把未来记录的绝对姿态误当当前相对增量。
- 从演示后续的一个有界窗口 `j ∈ [t+1,t+K]` 中，筛选相同操作阶段、可执行、不会跨越必要接触事件的候选目标。
- 根据命令的终点对齐、路径安全先验、位移及角度边界、任务进度和工具开销计算 Reward。
- 由当前 Policy 采样多个回答/工具命令，按 GRPO/PPO 等进行策略更新；**不是**对解析后的 Reward 直接 `loss.backward()`。

## 2. 奖励设计（候选）

第一步先定义 *真实可验证的东西* 和 *代理指标*，绝不混用。

定义候选集合：

$$
\mathcal K_t^{\mathrm{valid}} =
\{j>t: j\le t+K,\ \mathrm{samePhase}(t,j),
\ \mathrm{feasibleSegment}(T_t,T_j)\}.
$$
`feasibleSegment` 必须保守：至少检查目标动作可达、单步 bounds、可用的已知障碍几何或已验证的轨迹走廊；**不知道轨迹之间的自由空间就不能宣称碰撞安全**。

将模型输出映射为目标位姿 `\hat T(a)`，用相对位置和 SO(3) 测地旋转距离打分：

$$
d(\hat T,T_j)
=\alpha\|\hat p-p_j\|_2
+\beta\|\log(R_j^\top\hat R)^\vee\|_2.
$$
从局部有效轨迹点选择相近目标，同时防止选择远程跳过关键步骤：

$$
r_{\mathrm{align}}(a,t)=
-\min_{j\in\mathcal K_t^{\mathrm{valid}}}
\bigl[d(\hat T(a),T_j)+
\lambda_c C_{\mathrm{path}}(a,j)
-\lambda_p \Delta s_{t,j}\bigr].
$$
其中 `Δs_{t,j}` 是允许范围内的正向进度，`C_path` 是从当前到目标的**连续路径**约束，不能只看终点。系数均需用验证集与真实 Closed-Loop 指标标定，而不是按视觉效果人工调一个“理想曲线”。

动作边界代理：

$$
r_{\mathrm{bounds}}
=-\gamma_p[\|\Delta p\|-p_{\max}]_+^2
-\gamma_R[\|\log(\Delta R)^\vee\|-\theta_{\max}]_+^2.
$$
推荐总 Reward 先**分级门控**而非线性相加：无效工具 JSON、能力不支持、越界、碰撞未知且高风险、错误夹爪状态 → 低奖励或拒绝纳入推进奖励；合格动作再比对齐、正向进度与工具成本。避免出现“进度够大奖励可以抵消危险动作惩罚”的漏洞。

**硬边界必须由 Runtime 强制执行。** RL 奖励或惩罚只降低越界意愿，不是现实物理安全保证。

## 3. 不该做的事

### 错误 A：对整条轨迹找几何最近点

机器人在抓取前后可能经过同一 TCP 位置，但夹爪状态和目标物所处位置完全不同。最近点可能来自未来放置阶段，监督会鼓励模型“瞬移式”跳过接触。

**修复**：局部时间窗口 + 事件阶段一致 + 单调对齐 + 抓手状态 + 真实动作界限。

### 错误 B：把未来轨迹里的单步 `a_j` 当作当前状态合法动作

`a_j` 是从 `s_j` 出发的动作，不是从 `s_t` 出发。必须使用当前 FK 状态至未来 `T_j` 的相对变换，并检查该动作本身的路径。

### 错误 C：把离线对齐当作环境成功

真实示范记录了 `s_t --a_t*--> s_{t+1}`，但新输出 `a_hat` 的后果未知。**不能**假设 `s_t --a_hat--> s_{t+1}`。如果训练只是对每个静态记录的起始状态产生一步动作并评分，本质上更接近 *contextual-bandit-style policy optimization*，而不是具有真实环境转移的完整多步机器人 RL。

### 错误 D：用奖励替代一切动作示范

示范记录中的正确信息仍然珍贵，适当的固定 SFT BC 可以让模型先学会坐标、结构化参数和物理运动先验。RL 奖励再去优化不同但可接受的动作，而非从几乎零成功策略盲目探索。

### 错误 E：Reward Hacking

模型可能始终选择靠近演示轨迹但不前进的微小动作，或直接取最大合法步长跳跃。这些行为可能让几何代理值好看，却降低任务成功或增加碰撞。必须做“静止、反向移动、重复闭爪、跳过抓取、从轨迹外开始”等负例对抗。

## 4. 比较实验与可证伪标准

| 组别 | Loss/Reward | 在验证什么 |
|---|---|---|
| A. 原始动作 BC | 标准 SFT，对 next chunk 做交叉熵 | 当前基线 |
| B. 轨迹重标注 BC | 标准 SFT，监督目标从合法局部未来段中选择 | 时间采样偏好是否限制能力 |
| C. 动作对齐 RLVR | 不改变 SFT 模板，模型采样动作，以几何/阶段匹配打分 | 在无新环境交互条件下能否优化有效幅度 |
| D. SFT → C | 少量动作 BC，再 RLVR | 基础运动先验是否必要 |
| E. 闭环环境 RL | 真正执行动作，获得仿真状态和任务结果 | 离线代理奖励能否迁移到现实交互 |

比较必须固定基础模型、机器人任务集、图像输入、工具 schema、独立未见环境与 GPU-hours；同时报告：单步对齐分数、时间效率、越界率、物理成功率、实际碰撞、任务阶段失败、工具调用量。**C 比 A 的离线 Reward 高，不能单独认定研究成功；必须在 E 所代表的独立闭环环境上验证。**

## 5. 文献关系与创新空间

- [DTWIL（ICML 2025）](../papers/2025/dtwil.md)已经研究通过轨迹对齐与约束构造替代示范。直接使用“最近轨迹点监督”并非未经探索的新方向。
- [ReLIFT](../papers/2026/relift.md)、[BRIDGE](../papers/2026/bridge.md)提出在 RL 中灵活使用监督，而不是把所有能力变成同一个 Loss。
- [工具 Agent 受控比较](../papers/2026/sft-rl-tool-agents.md)警示：即使奖励容易计算，SFT 在某些调用准确率指标上也可能更优。

真正值得推进的创新点可能是：**同一组真实机器人记录如何在保持监督格式与执行安全契约不变的前提下，为通用语言工具 Agent 提供可变步长、任务进度与信息获取的可验证训练信号。**

## 6. 下一步先验收这些事实

1. 已有数据是否具有统一坐标系、机器人状态、TCP 姿态、时间戳与夹爪事件？
2. 哪些场景具备可验证的自由空间 / 路径碰撞信息？没有则不声称跨步动作安全。
3. Base 模型直接生成合法 `robot_act` 的比例及轨迹代理奖励分布如何？GRPO 八条样本有多少组带不同奖励？
4. 轨迹 Reward 比固定 Next-Chunk BC 好，是否体现在**真实仿真闭环成功率**上？
5. 即使几何评分表现良好，也必须验证未见机器人、相机、任务阶段及接触密集任务的外推能力。
