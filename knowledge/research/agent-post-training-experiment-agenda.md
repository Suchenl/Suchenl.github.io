# Agent 后训练：从争议主张到可证伪实验

> **性质**：公开、通用的研究实验议程（2026-10-20），**不是已经开展的实验报告**，不包含私有机器人项目内部数据或未经公开的实验结果。先阅读[研究主张证据地图](../topics/llm-agent-training/reviews/evidence-map.md)，再决定是否值得实施。算法、数据预算与成功定义在实验前冻结。

## 0. 不应把研究问题定义成「哪种训练方法更强」

更科学、可测的总问题：

> **在相同基础模型、可见工具/观测、训练信息与总计算/环境预算下，新的策略更新方法，是否在真实可执行任务、偏离示范的状态和长期能力保持上，产生稳定且不可被更便宜的 SFT 或数据覆盖解释的增益？**

它把原来模糊的“训练 RL 是否值得”拆为三个子问题：

- **信息增益**：额外的专家示范、真实工具反馈、环境观察、答案验证器提供了什么新信息？
- **算法增益**：在可比的信息和成本下，GRPO、交替、混训、触发式监督是否比简单基线更好？
- **环境价值**：准确完成结构化 tool call 是否真的意味着任务成功，还是只会「输出看起来正确」？

## 1. 统一记录规范（无此记录不做方法对比）

一个实验单元按以下字段归档，所有组在评估前确定训练/测试切分：

| 字段 | 应该明确记录 | 常见失误 |
|---|---|---|
| 初始权重 | Base/Instruct、版本、视觉塔、初始工具能力 | 一个组用强 checkpoint，另一个组从弱 Base 起 |
| 任务分布 | Task family、场景、对象、初始状态、旧任务留出集 | 只按 episode 随机切分，泄漏同一场景模板 |
| 可见信息 | 图片、机器人状态、工具 schema、错误反馈、历史窗口 | 给训练器看了部署时看不到的未来状态 |
| 监督预算 | SFT 正确轨迹数、tokens、教师查询数、过滤代价 | 将额外高质量教师数据算作免费 |
| RL 预算 | 所有 rollout、样本长度、验证器调用、被拒绝组 | 只统计进入 optimizer 的「有效」样本 |
| 动作/工具执行 | 验证器是什么，工具是否真实运行，失败能否重试 | 把 JSON 解析通过当完成任务 |
| 训练开销 | 全量/LoRA 可训练参数、actor+learner+critic/参考模型 GPU-hours 与 wall time | 只给被部署模型计费，忽略辅助分支 |
| 评估单位 | 配对测试任务、固定初始种子、重复训练随机种子 | 把一次 rollout 的多次回答当独立样本 |
| 安全与回退 | 失败种类、硬约束执行层、超时、停止动作 | 用可学习惩罚代替强制碰撞/边界约束 |

**最低报告**：按任务家族分组的成功率及配对置信区间、每 episode 平均工具与环境调用、失败恢复率、原有能力保持、完整 GPU-hours 和总 rollout tokens。统计独立单位优先是**任务实例/独立场景及训练 seed**，而非同一轨迹的多个 token；对同一任务进行配对比较，避免忽略聚类相关性。

## 2. E0：先测当前模型有多少「能被验证的成功」

**研究目的**：决定是否存在 RLVR 可利用的学习信号，而不是先训练一个复杂模型。

- 固定任务集，记录当前模型不微调时的每题成功概率、解析失败、工具调用、长度与超时。
- 使用同一验证器独立测试：正确答案、工具参数合法、规划器/环境执行成功、真实任务完成，至少区分这四层。
- 对于二元奖励、独立同分布采样 $G$ 次且单样本成功率为 $p$ 的**仅供直觉的**概率：

$$
P_{\mathrm{mixed}}=1-(1-p)^G-p^G.
$$

当 $p$ 极小时，同问题大多数全错组没有常见组相对优势的奖励差，但“无正例”不能直接诊断为模型根本缺知识，可能是验证器或工具失败。

**证伪方向**：如果人工核验的成功轨迹很多，但自动验证器总判错，优先修验证器；如果 JSON 合法、计划可执行但环境成功率低，优先研究执行和状态反馈，不能用格式奖励自我安慰。

**进入下一阶段条件**：明确区分上述失败来源，并保存审计样本；否则暂停 RL 配方实验。

## 3. E1（最高优先）：SFT vs RL 究竟是信息差还是优化差？

**研究假设 H1**：在已有标注动作/工具数据比较密集时，**相同信息和总预算**下的更复杂 RL 配方未必优于数据多样化 SFT。依据是 [工具调用对照](../papers/2026/sft-rl-tool-agents.md)，但它不直接证明真实闭环任务的结论。

建议从可实际执行工具且能够核验结束状态的任务开始。对照组：

| 组 | 更新方式 | 数据和执行信息 |
|---|---|---|
| A | LoRA-SFT | 固定专家示范池 $D$ |
| B | LoRA-SFT + 多样化恢复轨迹 | 在相同示范预算内替换一部分常规轨迹为失败恢复状态 |
| C | Direct RLVR | 同一 Base，只有可验证执行结果；记录额外交互预算 |
| D | A → RLVR | 与 A 同样的示范池，继续利用执行奖励 |
| E（可选） | A + 交替 SFT Replay / RL | 与 D 尽量相同监督与 RL 数据总预算，比较调度 |

不要只报告“参数更新步数相同”，而要双视角比较：

1. **固定监督示范量与给定 RL rollout 限额**：研究新增执行信息是否提供能力。
2. **固定总成本（包括教师和环境）**：研究方法是否**值得使用**。

如果 D 相比 A 的改进只发生在标准函数名/参数，而 B 在端到端成功率上追平甚至超过 D，说明追加数据覆盖可能比 RL 更经济；反之如果 D 在未见错误状态的恢复率稳健领先，说明执行反馈提供了可能不可由已有示范代替的信息。

**停止规则**：E0 验证器尚不可信，或任务没有独立成功判据时，不开始 E1 的“大规模 RL 比 SFT”比较。

## 4. E2：定向补监督究竟比随机补监督强多少？

关联：[ReLIFT](../papers/2026/relift.md)与[TSRL](../papers/2026/tsrl.md)。

**研究假设 H2**：在相同教师查询预算下，根据当前失败状态选择演示，比随机添加监督更有效且旧技能退化更少。

最小实验四组：

- **Random-SFT**：以随机方式对当前访问状态请求固定数量专家演示。
- **Static-hard-SFT**：事先按初始模型失败率挑选同数量困难状态。
- **Online-hard-SFT**：持续按当前模型评估得到的困难状态更新选择。
- **Verified-hard-SFT**：只对**验证器可信、工具可用、失败原因可解释**的困难状态请求监督。

全部组必须匹配专家标签总量、可用工具、任务顺序与评测回合，报告**教师调用开销与旧任务能力**。可变触发阈值事先锁定，并单独把「更好的选择策略」与「请求了更多标签」拆开。

**反证实验**：人为注入一定比例的奖励误判或不可用工具。若触发式方案将大部分示范预算花在错误诊断上，而简单随机补监督更稳，说明“困难状态”触发器不能仅凭 Group Success Rate 决定。

## 5. E3：失败恢复究竟是 RL 独有能力吗？

关联：[回溯理论](../papers/2026/rlvr-backtracking.md)。

**研究假设 H3**：当监督示范只含黄金路径时，RLVR 可能比只做 BC 更容易获得回退能力；但当 SFT 也获得同样数量的偏离/恢复示范时，优势可能缩小。

对照矩阵：

| SFT 数据覆盖 | 无 RL | + 真实执行反馈 RL |
|---|---|---|
| 仅黄金成功路径 | SFT-G | SFT-G → RL |
| 含偏离与恢复轨迹 | SFT-R | SFT-R → RL |

测试集要单独构造：

- **理想起点**：与专家示范吻合的初始状态。
- **可恢复偏离**：错误工具调用、偏离目标、抓取失败但环境仍可继续。
- **不可逆偏离**：例如物体已经掉落或越过安全边界，不应强行要求“回到同一节点”。

指标要区分“尝试回退”“合法回退”“最终完成”及错误恢复耗时。对不可逆情况，停止或请求帮助也可以是正确策略。

**否定 H3 的结果**：若 SFT-R 在相同信息与成本下已与 RL 版本持平，则不能把回溯成功直接归因为 RL 算法；应追问恢复数据覆盖是否已解释差异。

## 6. E4：离线轨迹代理奖励是否引导策略走捷径？

关联：[真实机器人演示与轨迹奖励](robot-trajectory-reward.md)。

这个实验必须把两种奖励分开：

- $R_{\mathrm{proxy}}$：根据保存的参考轨迹计算的接近度、阶段完成估计或运动/姿态约束；
- $R_{\mathrm{env}}$：在执行后由真实环境/可信仿真反馈得到的任务成功、安全、接触等结果。

**实验 H4**：高 $R_{\mathrm{proxy}}$ 未必意味着高 $R_{\mathrm{env}}$，特别是在接触、换步长和未见物体状态下。

同一策略族中比较：SFT；SFT + 代理奖励 RL；SFT + 环境反馈 RL；混合奖励 RL。横轴看代理奖励，纵轴看独立执行成功率；重点人工审查**代理高分但执行失败**的轨迹。若代理分持续提升、环境成功率没有提升，不能宣称“动作优化已成功”。

尤其不能用历史轨迹的下一帧来评价一个**未执行的替代动作**并称为真实反事实观测。

## 7. E5：是否真的需要 BRIDGE/DYPO 式复杂协调？

放在 E1–E4 之后。原因是额外双层优化、辅助纯 RL 分支、多教师分布等都增加不可忽略的资源和解释负担。

**先测最便宜的反证**：在任务、教师数据和执行反馈相同情况下，固定比例混 Loss、交替更新、SFT→RL 是否已达到相同结果？

只有在出现**可重复的梯度冲突和性能退化**，并排除 reward 漏洞、数据泄漏与预算不等后，再尝试动态门控或元优化。

对 [BRIDGE](../papers/2026/bridge.md) 要额外记录纯 RL 辅助分支的参数、rollout/奖励估计与 wall time；对 [DYPO](../papers/2026/dypo.md) 必须控制多教师的外部信息和查询成本。不能以“相同训练 step”代替“相同可用资源”。

## 8. 推荐实施顺序与必要的停止点

| 顺序 | 要做的事 | 若失败如何处理 |
|---|---|---|
| 1 | E0：验证器/动作执行/错误归因可靠性核对 | 停止算法扩展，先修错误反馈 |
| 2 | E1：小规模 SFT、SFT+恢复数据、RL 与 SFT→RL 受控对比 | 若 RL 没有收益，先检验数据覆盖与成功组 |
| 3 | E3：黄金路径 vs 恢复轨迹的 2×2 实验 | 若数据已解释效果，论文贡献应改写为“数据与状态覆盖” |
| 4 | E2：在确认专家可获取时验证触发监督 | 若成本不合算，保留普通 Replay，不追逐触发新算法 |
| 5 | E4：检查代理奖励与真实结果不一致 | 如果发现 reward hacking，严禁只汇报代理奖励上涨 |
| 6 | E5：只有前述简单基线不足时研究复杂联合训练 | 相同 GPU-hours 下无增益则不投入大规模元优化 |

**预注册**：决定正式实验前写下评测任务、主指标、样本数/seed、可接受的最小实际收益、统计方法与停止条件。此文故意不虚构“已经跑过的实验”或替项目设定未经确认的数值门槛。

## 9. 能形成什么可发表的研究结论？

- 若某个**信息来源**（例如可执行失败反馈）在同预算下提供 SFT 不能获得的可恢复能力，可以研究其最小必要信息与泛化边界。
- 若更复杂 RL/SFT 协调**没有**战胜监督数据覆盖与简易交替配方，这依然是有价值的负结果：指出额外计算何时不值得。
- 若离线代理奖励与真实成功发生系统性背离，可以研究**奖励有效性与可验证性边界**，而不是再换一个训练算法名称。

实验真正的价值是把“用了某个 RL 算法”变成“**在何种信息和环境条件下，哪种学习信号有不可替代的价值**”。
