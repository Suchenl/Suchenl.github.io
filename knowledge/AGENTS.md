# AI / Coding Agent 知识库维护规则

**此文件是维护约定，不是具体技术观点的来源。阅读后再修改仓库。**

**单一维护位置**：`Suchenl/Suchenl.github.io` 仓库的 `knowledge/`。网站 `/research/` 直接由这里渲染。不要再向 `Suchenl/sus_research_review` 写新知识；那是迁移前的只读快照。

## 一、语言与分工

- 使用简体中文写作和维护。保留原论文英文标题、作者姓名、会议名、模型名、URL 和必要术语原文。
- `topics/` **综述**：回答研究问题，比较论文的共同点/差异/冲突；可提出研究判断但必须标为“分析”。
- `papers/` **单篇文献**：同一论文只有一个主卡片，包含元数据、方法详解、目标/公式、实验结论、弱点和适用边界。
- `glossary/` **共享术语**：同名术语唯一权威定义，别在各文献重复建一份互相冲突的定义。
- `research/` **个人研究推论**：记录候选方法、假设、反例、实验路线，不得把它们描述为原论文贡献。
- `CHANGELOG.md` **更新日志**：记录用户可感知的修改；不复制正文。

## 二、事实核验与禁止行为

1. 新增文献前**联网查证原始来源**（会议官方/论文原文/官方项目页）。至少有一个真实可打开的论文链接；不要只使用别人写的二手总结。
2. 发布年份、初版时间、当前最新版本、会议是否录用、作者及定量实验都需要核实；未确认就写“待核验”，不能猜。
3. 清楚分离 **论文报告**、**作者分析**、**推论/假设**。统计差异、收敛速度和资源预算不能跨不同设置直接比较。
4. 对近期论文标注“截至哪一天已核验”，动态事件不用静态知识冒充最新事实。
5. 不大段转载论文内容，不直接复制已有网络中文综述；用自己组织的中文解释、公式、链接和简短必要引述。
6. 非用户明确要求，不删除旧研究问题、失败路线或人工结论；要写清楚“被什么证据更新/取代”。
7. 不为了新增方向创建一套新 README+glossary+文献副本。遵循现有路径。
8. **不得宣称 GitHub 知识库会自动联网更新**。没有实际任务/CI/计划时，只能说“适合持续增量维护”。
9. Git 操作应小批提交，提交信息说明更新主题；不要 force push，不对仓库做大规模历史重写。

## 三、新文献处理步骤

1. 搜 `papers/` 是否已有该论文（arXiv ID/DOI/正式标题）；先更新原卡片而非新建。
2. 读原始论文的摘要、方法、实验、限制；记录作者/年份/发表状态/模型/数据/指标/开源状态和核验日期。
3. 用 `templates/paper-note.md` 写单篇解读（优先深度理解而非堆论文）。
4. 更新 `papers/README.md`；相关的 `topics/.../reviews/` 只做归纳和指向这张卡片。
5. 如果出现新的术语，只在 `glossary/` 下的适当主题定义，交叉链接。
6. 在 `research/` 单独记录对研究项目的可执行启发和反例。
7. 运行 `python knowledge/scripts/check_kb.py`，修复失效的**仓库内部**相对链接；外链需人工或联网工具核实。
8. 更新 `CHANGELOG.md`；检查 Git diff 后提交。

## 四、AI 更新综述时的输出契约

每次报告：新增/更新文献数；发表/开源状态变动；被修订的旧结论；争议点及证据；失效链接；提交 SHA；未解决的问题。没有新证据就不要为了“看上去有更新”重复改写。

## 五、当前领域特别警告

SFT、RLVR、OPD、离线 RL、RL 奖励模拟之间的训练信息源不同。**“使用离线轨迹来给当前模型输出打分”可以属于 on-policy 采样的可验证任务，但它不自动形成新的真实环境转移。** 不能用未执行的预测动作直接索引出其假想物理后果；不要把匹配示范轨迹等同于任务成功或安全。

## 六、统一 Research 的论文元信息（2026-10-19 起）

- 唯一论文文件存于 `knowledge/papers/<首次公开年份>/<稳定英文短名>.md`。禁止再向 `web/src/content/papers/` 添加论文，也不得同时在其他目录维护第二份正文。
- frontmatter 推荐 `title`（英文原始标题）、`year`、`categories`（中文层级数组）、`summaryZh`、`status`、`rating`、`tags`、`authors`、`venue`、`links`。正文逐层加深，不强制每篇收藏立即补成完整综述。
- `categories: ["生成模型/视频生成", "世界模型/长期记忆"]` 表示同一论文在两个文件夹下都能被找到，不复制文件。分类由元信息决定，不由存储年份决定。目录节点由页面自动构建。
- `status` 只接受 `to-read`、`reading`、`read`、`untracked`。没有用户本人提供的阅读状态时默认 `untracked`，不能因为 AI 已写解读就推断用户已经读过。
- 单篇论文可先只有引用与一句中文摘要，再补方法、公式、实验、批判性分析。保留旧笔记，不随意编造原始作者/来源/录用状态。
- 主题综述应链接论文唯一笔记；站点的论文详情页自动根据 Markdown 交叉引用显示相关主题综述。
- 旧 `/reading/` 只作为 `/research/` 重定向。AI 更新页面时必须检查唯一数据源、中文目录、移动端布局和 Astro 构建结果。

## 七、读者界面与公式

- 优先为长篇研读设计：适中宽度、良好标题层级、可跳转章节、响应式代码/公式/表格。
- 从研究目录能同时看到相关专题综述、术语、研究假设和论文列表；不要再把阅读清单与研究分析割裂。
- LaTeX 展示公式使用 `$$ ... $$`，行内使用 `$ ... $`。禁止让 LaTeX 源码原样作为普通段落输出，生产构建需检查实际 KaTeX 结果。
- 字号和专注模式是本机浏览器偏好，阅读进度是临时页面状态；它们并不修改 GitHub 知识库。

## 八、前端交互验收契约

- 文件夹目录遵循 WAI-ARIA Tree View Pattern（https://www.w3.org/WAI/ARIA/apg/patterns/treeview/）：整行有同一个主操作区，点击文字、箭头、数字区域都能展开/收起，且能选中分类；使用方向键、Home/End、Enter/Space 浏览。
- 分类选择须可被浏览器前进/后退恢复；进入论文后返回须能回到来源目录，不能只返回默认第一个分类。
- `aria-expanded`、`aria-current`、可见键盘焦点、足够尺寸的点击区是底线；不要只在图标上绑定点击事件。
- 手机端导航为可开关菜单，Escape 可关闭；文章目录链接跳转后自动关闭移动端展开面板。
- 优先保持页面可读和可操作（WCAG 2.2），特别关注键盘、缩放、颜色对比、触摸控件、减少动画偏好和公式/表格的横向溢出。
- 每次上线运行 `npm run build`，并参照 `docs/UX_AUDIT.md` 手工验证关键行为。静态构建检查不能替代浏览器实际交互测试。

## 九、循序学习与知识关联（2026-10）

- `knowledge/paths/` 采用人工排序的学习步骤，每步写 `ref` 和 `why`。AI 可以提出步骤调整，但不能因为发布时间更近就自行把完整知识依赖顺序颠倒。
- 单篇论文、综述、术语和研究假设的链接由现有 Markdown 或路线 `steps.ref` 生成；禁止复制第二份正文来构建关系网。
- `glossary/*.md` 的 `##` 标题是术语索引的唯一来源；要保证定义、例子、非等价概念等人类可理解的解释，不要制造空术语占位符。
- 阅读器记录章节和学习路线勾选只存储于浏览器 localStorage；任何浏览记录、勾选都不代表用户本人宣称已读，不能反向改写论文 `status`。
- 阅读辅助自测题是理解建议，不是自动生成的考试评分或论文准确性验证。
- 新增/删除笔记务必检查逆向链接、路线步骤和站内数学内容；`npm run build` 应验证学习路线目标与渲染产物。

## 十、阅读学习便利性与个人草稿

- 所有长文的解释应支持「一句话要点 → 研究问题 → 方法及公式 → 实验与局限 → 我的理解」逐层深入；不能只堆砌大量论文标题。
- 新的学习路线应说明为什么安排这个阅读顺序。关键术语直接定位到唯一词典中的对应二级标题；论文关系以有证据的链接为准，不自动臆测相似性。
- 阅读后的复述题只用于主动回忆，不当作原文已经被正确理解的证据。
- 本机学习笔记使用 `research-personal-note-v1:` 前缀保存在 localStorage，必须能复制成 Markdown 手工备份；本地保存失败要显示明确警告。严禁在页面上宣称已经同步到 GitHub。
- 「已读」只能由用户自己设定；点击、路线勾选、页面停留或填写个人笔记均不能自动修改它。


## 十二、整站发布与知识库一致性

- 首页围绕当前研究方向和公开代表作品。论文数据在 web/src/data.ts 唯一维护；工具数据在 web/src/data/projects.ts 唯一维护。Projects 可读取论文数据，但禁止生成重复事实。
- About 汇总经历、能力与合作入口；/work/ 与 /expertise/ 均保留历史 URL。导航重新整理时需检查键盘和移动端布局。
- 未获允许不得公开私有研究仓库（含 Open-Robot-Agent、UniRobo-Data、VMem-Bench、AgentHarness3D）的源代码、截图、内部实验和指标。
- publication 预览使用可访问 dialog；Blog 分类筛选必须是按钮组而不是伪 tab；未知统计不得当作 0。
- comparison 文献卡片字段必须有原始证据。related 条目包含 ref、type、note，type 只接受 compares/extends/requires/questions/supports；不得将主题相似度自动视为正式引用或因果支持。
- Research 本机学习笔记的 JSON 备份/恢复由读者主动操作，不得隐式上传；阅读勾选不等同于已读状态。
- 变更后依次执行 Astro build 和站点静态校验、Chromium browser smoke，必要时对比 Lighthouse 指标。不以构建成功替代页面实际交互验收。


## 2026-10-20 用户体验决策（以此为准）

- **不再提供个人学习笔记输入、浏览器笔记备份/导入界面**。用户希望 Research 专注于阅读、综述、对比和术语，不把它做成个人笔记软件；勿按旧的功能清单恢复这些控件。
- Publications 的框架图为静态缩略图，**不要添加遮挡图像的悬浮「放大查看」或图片弹窗**。每篇论文使用原生 details/summary 展开简明介绍：动机、方法、主要发现、证据边界。
- Publications 额外按已公开发表/发布年份展示研究成果时间线；绝不能把公开年份写作课题启动年份，不制造内部研究经历日期。
- 首页研究方向使用易理解的具体说明，不再用宽泛、语义重叠的标签填满区域。Projects 不使用“小项目”或 side projects 这样的自我贬低说法。
